## 1. What genuinely works

- **Auth** — Supabase Auth; `requireUser` verifies the bearer token server-side on every `/api/*` call.
- **Upload path** — ticket → presigned PUT **direct to B2** → confirm. Confirm verifies the object with HEAD
  (ranged-GET fallback), rejects and deletes on a mismatch with the declared size, enforces a MIME/extension
  allow-list, and recomputes the category from server-side values. Bytes never touch our compute.
- **File manager** — folders, breadcrumbs, rename/move, trash/restore/permanent delete, favourites, folder pin
  and icon, recent, activity, bulk actions, search/sort/filter. Quota is maintained by a Postgres trigger.
- **Sharing** — public links (view/download, expiry, revoke) and private invitations by email, with RLS
  policies granting shared read on `files`/`folders`.
- **Payments** — Stripe checkout is real: a paid plan returns a checkout URL and records `past_due` +
  `pending`; only the signed webhook activates the plan. Free downgrade applies immediately. Provider keys are
  stored encrypted (`payment_settings`, `SETTINGS_MASTER_KEY`).
- **Admin** — HMAC-signed staff JWT, `admins` table, role hierarchy enforced server-side (`requireAdmin`), and
  real endpoints for stats / users / user detail / user files / payments / audit / analytics.
- **Developer portal** — API keys generated with prefix + hash (secret shown once), webhook CRUD with HMAC
  signing, usage query, API plan catalogue.

## 3. Flutter (`cloudcolsProject/flutter-project`)

**It has never been compiled here.** `flutter` is not on PATH, so there is no `analyze`, no test run and no
build for this project — everything below comes from reading 5,642 lines of Dart.

The structure is sound: Riverpod + go_router + dio, repository interfaces with mock and API implementations
behind `AppConfig.isApiEnabled`, secure token storage, and a transport seam for tests.

### Blocking bugs — the app cannot talk to the backend as written

1. **No `Authorization` header is ever sent.** `DioTransport.get/post/patch/delete` take a `token` parameter
   and ignore it. Every authenticated request returns 401. (`lib/core/network/api_client.dart`)
2. **Every path is wrong.** `_url(path)` = `AppConfig.apiVersion + path` = `/v1/files`. The backend serves
   `/api/files`. Nothing resolves.
3. **Upload confirm always fails.** Flutter posts `/files/confirm` with only `uploadId`; the server requires
   `fileId` and answers `FILE_NOT_FOUND`.
4. **The presigned PUT sets `content-type`.** The web client deliberately does not, because B2 rejects a
   Content-Type that disagrees with the signature. This upload will 403.
5. **`/files/usage` shape mismatch.** Flutter expects `{usedBytes, quotaBytes, categories[]}`; the server
   returns a bare array. The storage screen will always read 0.
6. **`ApiBackupRepository.pickFiles()/pickFolder()` return `const []`** in API mode.
7. **MIME is guessed from a coarse type string** (`image` → `image/jpeg`), so server-side categorisation is wrong.

### Scope gaps vs. Phase 11–12

No preview or media playback of any kind (no video, image or PDF packages in `pubspec.yaml`), no sharing, no
notifications, no trash, no plans or billing, no general upload outside backup jobs. What exists is a
**device-backup companion**, not the mobile file manager the plan describes. Android release configuration
(signing, icons, Data Safety) has not been started.
